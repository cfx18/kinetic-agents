# 不扩展610工况池的任务扩展草案

日期：2026-09-16。用户问题：在不增加计算池的情况下，可以沿不同科研活动扩展多少问题？

状态：任务分类与可评性设计建议，不是已构建题包、已验收grader或已批准的新实验。没有新求解、模型调用、运行干预、评分变更或训练。

## 1. 资源边界

将“不扩池”解释为不新增评测工况/实验观测。它不等于不给新方法计算已有工况，也不等于零模型费、零后处理CPU。若进一步要求零新增ODE/PDE求解，只能做已有结果可支持的离线研究与组件测试；未知候选的性能不能靠旧矩阵凭空获得。

现有资料来源：

- [610审计](POOL_610_AUDIT_20260916.md)：320 IDT、290 1D LFS、18燃料标签，历史暴露集合；来源/计量适用性仍有待核验项。
- [方法与工具审计](PAIR_METHODOLOGY_DRGEP_AUDIT_20260916.md)：真实图表示缺陷、源证据获取轨迹与已保存状态复算；修复局部bug不自动改变最终候选。
- 已结束轨迹的候选、误差、失败、公开行动与输入输出。任何需要恢复环境的任务必须先核验状态可恢复性，不把最终文件倒填为历史文件。

## 2. 12类候选任务

这12类按交付物与验收问题区分，存在能力重叠，不宣称12个独立化学体系或12条已获证论文贡献。

| ID | 科研任务与示例要求 | 交付物/验收依据 | 新增ODE/PDE求解 |
| --- | --- | --- | --- |
| F01 | 研发更有效的机理优化算法；不能只提交一版更小机理 | 可执行方法；同应用域/资源下与预定基线比较，报告失败与成本；同USC任务结果仅支持同域 | 需要，仍用旧工况 |

## 3. 可交付规模与计数

建议第一版目标为12类×每类2个经过验收的实例=24题；这只是规划目标，当前未完成逐题材料与可判分验收，不报告“已有24题”。若某类只有一个真实可用来源，就减少题量，不补虚假实例。

以后从完整轨迹提取更多决策检查点，需要按真实可恢复状态和证据独立性清点数量；不能预先保证几百个有效检查点。提示改写、同轨迹切片、同父候选均可作为训练材料，但必须记录共同来源，不能随机拆分后声称未见科学任务泛化。

建议首批聚焦F01（方法研发）、F05（跨工况验证设计）、F07（跨工况修复）；F10/F09/F12作为同一科研任务中的关键能力，而不是为凑数量转向纯问答/工具接口题。F06可先离线诊断grader可行性，不把固定候选库回放当作主线优化实验。

## 4. 复用Grader的正确方式

共用底层工况/求解器/原始误差服务，而不是所有任务套相同总分。

- 机理成果：原任务适用域内的压缩、误差、覆盖、失败。
- 方法性能：上述成果再加实际与逻辑成本、重复稳定性；新父泛化仍需新父任务。
- 科学证据：来源支持、适用性、缺口、可复现性，需要专家校准的证据rubric。
- 工具与恢复：可执行测试、恢复后的成果，以及错误发现与错误修复分别记录。

用户提出的6/4压缩—精度权重不能直接给文献检索或工具修复评分。共享底层实验库可省数据整理，不消除不同交付物的验收规范设计工作。所有新评分头均为未冻结草案，不能回写历史榜单。

## 5. 不扩池的科学上限

可以扩科研活动与决策场景，不能据此扩展到低温/新观测、未覆盖燃料化学、2D/3D、soot的实证。也不能把同USC家族的方法设计/修复任务当作跨父泛化证明。新算法要证明优于基线必须实算；仅查看旧机制—工况矩阵只证明离线选择/估计能力。

当前610已历史暴露，若用于训练，不能再叫同池盲测。未用于某一次训练的片段也不等于来源独立。对算法提交应冻结代码/输入边界，再使用隔离评价资料执行；不能由算法自行挑有利案例作为最终评分。

## 6. 合成数据的生产方式（2026-09-16补充调研）

用户询问通用合成数据如何制作。本轮仅解释与调研，不生成新付费轨迹或启动训练。

四种可以组合的方式：

1. 种子任务扩写：[Self-Instruct](https://arxiv.org/abs/2212.10560)从少量种子生成instruction/input/output并过滤无效和相似样本。适合扩大表达/约束多样性，生成答案并不自动是真值。
2. 由可信材料反向出题：[Instruction Backtranslation](https://arxiv.org/abs/2308.06259)从已有文本生成对应指令并筛选。科研场景可以从已核验报告/代码/结果构造任务，但仍需单独核验题目可解、输入充足和答案适用；原文也不是天然正确。
3. 在真实环境采样执行：[WebDancer](https://arxiv.org/abs/2505.22648)结合问题构造、轨迹采样、筛选、SFT与RL。迁移到本项目意味着模型实际检索、编程、调用求解器；只保留可观察公开I/O，不补写未记录的过程或隐藏推理。
4. 从失败状态分支恢复：[RoTS](https://arxiv.org/abs/2605.29447)构建可回放轨迹树，探索错误并生成恢复续接。借鉴的是方法，GUI结果不能证明化学有效；原快照不全的历史点只能重建并标记为重建，不能伪装原状态。

建议本项目的流程：核验种子任务与材料 → 按任务种类/信息条件/真实失败模式生成变体 → 静态检查可解性/隔离/重复 → 在独立环境采样多个续接 → 科学工具核验结果，专家校准证据rubric → 保留成功、失败、争议与来源 → 按用途导出SFT/偏好/在线RL任务。

SFT可用执行验证过的正向续接；失败前缀作为条件，不作为应模仿的正确动作。偏好数据需比较同一输入/状态下的续接，标注比较依据及成本，允许平局和无法判断；不是机械按最终均值判所有过程好坏。RL中后续轨迹可在线生成，无需预先提供唯一标准动作，但环境及奖励检查必须可靠。三条为不同训练路线，非要求同时实施。

合成的是题面、配置、方案和行动路径；在本项目科学训练轨迹中，实验观测、工具返回和新增候选误差必须来自真实来源/实际执行，不能由LLM编造。父预测生成的标签明确标为模拟参考，不是实测。人工错误注入须标为构造扰动，不能冒充历史事件。专家提示可用于帮助教师生成合格示范；如把这些提示从学生输入移除，必须重新检查剩余信息是否足够支持该决策。

保存每条样本的parent_task/source_group、信息截止点、原始输入与返回、状态/结果身份、模型/工具版本、实际成本、标签来源和训练用途。先按底层任务/来源确定训练与评测隔离，变体和分支继承分组；历史610衍生训练不构成同池未见评测。重复采样和核验成本不能因“合成”而不记账。

### 开放检索GT的限制（2026-09-16补充）

用户指出“查材料的GT不好给”。确认这是实质标注瓶颈，不能用LLM-as-judge消除未知真值，也不能据此承诺所有检索题可自动扩为硬标签数据。

[NIST TREC说明](https://trec.nist.gov/pubs/trec33/papers/overview_33.pdf)指出完全相关性标注不可行，采用多系统结果pooling抽取待审文档；将未标注视作不相关的传统处理在浅池下会产生偏差。可以借鉴多路检索汇总后专家复核，而不照搬“未知来源即错误”。[ResearchRubrics](https://arxiv.org/abs/2511.07685)提供人工任务特定标准与模型/人类审阅，不能代替来源事实的独立核验。

可选三条路线（尚未选择/冻结新的评测协议）：

- 有限固定文献库：标注有关证据，能较可靠检验抽取/排序/适用性；但不是开放互联网发现能力，语料不全仍应披露。
- 开放网络、可验收的证据交付：不指定唯一论文，要求少量关键证据及定位、字段、适用范围；已知参考源只作可接受见证，不是穷举答案。新来源进入复核，未判定不算负例；仅报已审证据质量和预先规定的信息需求覆盖，不声称全网召回率。
- 完整科研任务内的检索：科学产物由执行评价；对关键证据作辅助审查。最终成功不能反推检索必然正确或有因果贡献，也不能把低成本搜索策略当已获证的最优策略。

数值、单位、原文定位等可建立较硬标签；是否适用/是否足以改变策略通常是专家审阅的集合式判断。建议先做少量可核验的证据交付任务，保留NA/争议和未知来源，校准judge后再扩展；不把24题规划当成24个已建立硬GT的任务。原610题库、评分、运行、预算和训练状态不变。

## 7. 本轮位置与下一步

当前位置：benchmark/任务体系与训练数据设计，尚未新增算法、PDE或RSI证据。核心交付为有边界的12类任务清单与24题设计目标，非现成可训练数据。主要卡点是科学groundtruth/专家标签、状态可恢复性、同源数据泄漏与后续执行预算。下一步建议先核验F01/F05/F07各一个实例的输入、交付物和验收契约；新任务运行/新成本/评分冻结另按项目review规则处理。
